### 事务四大特性和隔离级别

#### 事务四大特性：ACID

​	A（原子性）C（一致性）I（隔离性）D（持久性）

| 特性                          | 通俗理解                                                     | 核心要点                                | 实现技术（了解即可）        |
| :---------------------------- | :----------------------------------------------------------- | :-------------------------------------- | :-------------------------- |
| **原子性（Atomicity**）**     | 事务里的操作**要么全做，要么全不做**，没有一半。             | 中间出错要回滚（Rollback）。            | undo log（回滚日志）        |
| **一致性（**Consistency**）** | 事务执行前后，数据是**符合业务规则**的（如转账前后总金额不变）。 | 这是最终目标，A、I、D 都是为 C 服务的。 | 靠应用层约束 + 其他三个特性 |
| **隔离性（**Isolation**）**   | 多个事务同时执行时，互不干扰。                               | 隔离级别越低，并发越高，问题越多。      | 锁 + MVCC（多版本并发控制） |
| **持久性（**Durability**）**  | 事务提交后，数据**永久保存**，即使宕机也不丢。               | 提交即保证不丢失。                      | redo log（重做日志）        |

#### 并发事务的三大问题：脏读、不可重复读、幻读

| 问题           | 通俗描述                                                     | 例子                                                         |
| :------------- | :----------------------------------------------------------- | :----------------------------------------------------------- |
| **脏读**       | 读到了**别人还没提交**的临时数据，万一别人回滚，你就读错了。 | 事务A改工资为10万（未提交），事务B读到10万，然后A回滚 → B读了个寂寞。 |
| **不可重复读** | 同一个事务里，**两次读同一条记录**，结果不一样（因为别人改了它）。 | 事务A第一次读到余额100，事务B改成200并提交，事务A第二次读到200 → 前后不一致。 |
| **幻读**       | 同一个事务里，**两次查询符合条件的记录数量**不一样（因为别人插入/删除了）。 | 事务A查id>5的有3条，事务B插入一条id=6，事务A再查变成4条 → 像出现了幻觉。 |

#### 四种隔离级别：读未提交、读已提交、可重复读、串行化

| 隔离级别                         | 解决脏读？ | 解决不可重复读？ | 解决幻读？ | 并发性能         | MySQL默认？         |
| :------------------------------- | :--------- | :--------------- | :--------- | :--------------- | :------------------ |
| **读未提交（Read Uncommitted）** | ❌          | ❌                | ❌          | 最高             | 否                  |
| **读已提交（Read Committed）**   | ✅          | ❌                | ❌          | 高               | 否（Oracle默认）    |
| **可重复读（Repeatable Read）**  | ✅          | ✅                | ✅*         | 中               | **是**（MySQL默认） |
| **可串行化（Serializable）**     | ✅          | ✅                | ✅          | 最低（完全串行） | 否                  |

#### 事务实现原理：

| 技术           | 作用                                       | 关联特性/级别      |
| :------------- | :----------------------------------------- | :----------------- |
| **undo log**   | 记录修改前的旧值，用于回滚和MVCC读旧版本。 | 原子性、MVCC       |
| **redo log**   | 记录修改后的新值，提交后即使宕机也能恢复。 | 持久性             |
| **锁（Lock）** | 写时加锁，防止别人同时改。                 | 隔离性             |
| **MVCC**       | 读的时候读一个快照，不阻塞写，提高并发。   | 读已提交、可重复读 |

**MVCC 简记**：每个事务启动时拍一张“快照”，读的时候读快照里的旧数据，写的时候才加锁。

#### MySQL 默认 RR（可重复读）

## 一句话总结

> **ACID 是保证事务正确的四个特性，隔离级别是在并发和正确性之间做的权衡。MySQL 默认用“可重复读”+MVCC+间隙锁，既避免了脏读、不可重复读和幻读，又保持了较好的并发性能。**
